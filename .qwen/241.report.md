# 241 report: question gate inverted to a pleasantry list; lead-in fillers; vocabulary

Branch `w/241`, worktree `~/AI-231-ME4-w241`. Read first: `docs/ME4-VOICE-SESSION-FINDINGS-2026-11-26.md` (Cause 2 and 3).

## The bug

Fix 235 skipped the documents in the router branch when `not doc_route.question_like(said) and not doc_route.document_cue(...)`. `question_like` only accepted utterances that START with a question word, so spoken lead-ins dropped real questions: "Got it, what's the office Wi-Fi password?", "Sorry, I mean who won the mayor race?", "On which day do NYU Abu Dhabi classes follow a Monday schedule?", "The At SDR module mentions a law from 2010. Who signed it?", "Broadly speaking, what are all the documents about?", "This was California's commercial electricity price in August 2026." (all six from the findings).

## What changed

### 1. `pipeline/src/voice_pipeline/doc_route.py` — `is_pleasantry(said) -> bool` (new)

- True when the utterance, lowercased with punctuation stripped, is at most 6 words AND every clause (split on `[.!?]` and commas) matches the closed list `_PLEASANTRY_PIECES` (greetings, thanks, acknowledgements, repair apologies, closings; combinations like "Hello, good evening." and "Got it. Goodbye." are True).
- False when the utterance carries a wh-question word, a digit, or a `document_cue` (document/file/... word) — a pleasantry can hide a real question.

### 2. `pipeline/src/voice_pipeline/doc_route.py` — `question_like` reworked

- Leading fillers stripped first, repeated, comma-separated: got it / understood / alright / all right / sorry / sorry i mean / i mean / right / so / well / now / actually / broadly speaking / okay then (plus ok / okay / hey / please / so / and / can you tell me / could you tell me / tell me, which the old regex already accepted as a single optional prefix).
- Start words gained: "on which", "in which", "during which", "for which", "at which", "to whom", "how come", "tell me", "i want to know", "i'd like to know", "do you know".
- A wh-word or auxiliary starting a clause after a comma/period counts ("The ATSDR module mentions a law from 2010. Who signed it?" → True).
- Additionally, a wh-word or auxiliary ANYWHERE in the utterance counts. This one line is deliberate and worth a second look: the ticket's test table requires `question_like("This was California's commercial electricity price in August 2026.")` to be True, but that garbled utterance has no question word at a start position or after a comma/period — no narrower rule can reach it. ASR mangled the real question word ("What was ..."), so any surviving auxiliary means "worth a document check". Consequence (accepted, matches the ticket's "send everything else to the documents" policy): statements that merely contain an auxiliary ("The meeting is at three.") are question-like; in the router branch that is harmless (they go to the docs check exactly as before 235) and in the no-router branch they get a checked docs pass instead of straight Gemini. Home commands (`_COMMAND_START`, unchanged, checked first) and closed-list pleasantries stay False.
- `_COMMAND_START` exclusion semantics kept: "turn on the lights" and friends are still not questions; the ACTION calls before the gate in `agent_server.py` are untouched.

### 3. `pipeline/src/voice_pipeline/agent_server.py` — router-branch gate inverted (line ~1297)

`not doc_route.question_like(said) and not doc_route.document_cue(...)` became `doc_route.is_pleasantry(said) and not doc_route.document_cue(...)`. Result: pleasantries skip (route "routed", no docs call, no prefix, the router's own reply answers); every other utterance, including statements and commands without a cue, goes to the docs check exactly as before 235.

**No-router branch (line ~1232) deliberately NOT inverted.** I read it as the ticket asked: its `question_like` gate is not the 235 gate. `git log -L` shows it was introduced in `771d0b0` (the original Pi no-router design: "every question goes to the checked document path first; commands and chit-chat fall through to Gemini below") and touched by `217`/`221b`, not by 235. Its fall-through is Gemini/implicit-docs, not "routed with the router's reply", so inverting it would change pre-235 no-router behaviour beyond what this ticket asks for. It still calls `question_like`, so it benefits from the fixed classifier (lead-in and garbled questions now reach the docs there too) without any branch change.

### 4. `config/entities.json` — vocabulary (Cause 3)

The file is a flat `{name: category}` dict (1444 entries, all string values) — there is no `variants` field; each spoken form is its own entry (the hotword writer derives lower + Title case per name, and the repair ladder matches spans against the named categories). Appended, in the same shape, without disturbing existing entries (now 1456):

- canonics as `term` (repair targets for the `--slot "doc+term?"` ladder, which searches only the `term` category): "Wi-Fi", "per diem", "ATSDR", "QCAS", "mayor race"
- misheard spoken forms as `other` (Parakeet hotword bias only — never repair targets, so a transcript "Wi Pi" / "At SDR" / "Q C A S" / "per diamond" / "per dime" / "A T S D R" / "wifi" is still repairable to the canonical): "wifi", "Wi Pi", "per diamond", "per dime", "At SDR", "A T S D R", "Q C A S"

Adding the misheard forms as `term` would have been wrong: an exact listed name is treated as already-correct by the repair step and would never be fixed.
