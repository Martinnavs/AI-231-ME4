# 252 report: unsupported files are recorded, junk is ignored

Branch `w/252`.

## The bug

The standalone ingest writer (`src/voice_agent/rag/ingest.py`, folder path) built
`supported = [f for f in files if f.suffix.lower() in SUPPORTED_EXTENSIONS ...]` and
silently dropped everything else BEFORE the DB write. So `.json`, `.xml`, `.odt`,
`.ods`, `.eml`, extension-less files, etc. never appeared in the `files` table and the
agent could never say "I couldn't read that file". (The live `DocIndex` path and the
zip ingest path were already fine: they call `load_file` per member and it returns
`status="unsupported"`, which gets recorded; zip junk is filtered by
`zipingest.validate_members`. The gap was only the folder path of the ingest writer.)

## What changed

### 1. `src/voice_agent/rag/ingest.py`

- New module constant (the one small, generic junk list):

  ```python
  JUNK = frozenset({".ds_store", "thumbs.db", "desktop.ini", "__macosx"})
  ```

  plus `_is_junk(rel_key, size)`: zero-byte files are junk; any path part (file or
  folder) whose lowercase name is in `JUNK` is junk (this is what catches
  `__MACOSX/...` subfolders and `Thumbs.db`/`.DS_Store`/`desktop.ini` regardless of
  case or location); dotfiles / `~$` / `.~lock` prefixes are junk (already skipped by
  `_walk_folder`, kept here so the rule is self-contained).

- In `ingest()`'s folder path, the walk result is filtered through `_is_junk` BEFORE
  the supported/unsupported split. Note `desktop.ini` is a `.ini`, which is a
  SUPPORTED extension — it used to be parsed and could even produce a chunk; it is
  now fully ignored. Same for zero-byte files with supported extensions (they used to
  be recorded as `empty` failures; they have 0 chunks either way, so chunk counts and
  texts of other files are untouched).
- Every remaining unsupported file is recorded ONCE in `files`:
  `status="unsupported"`, `error="unsupported file extension: <ext>"` (same wording
  `load_file` uses on the live path), `kind=<ext without dot> or "unknown"`,
  `note=<ext>` (the short extension, per ticket), real `size`/`mtime_ns`/`ctime_ns`,
  `n_chunks=0`, no sha (the file is never read). `INSERT OR REPLACE`, no chunks
  written, no file cards, no images.
- The unsupported rel_keys are added to `seen_keys`, so (a) the stale-key deletion
  loop at the end of the run does not delete them, and (b) re-ingest is idempotent
  (the row is refreshed in place; an unchanged tree yields a byte-identical `files`
  table and identical `chunk_data`). A junk file that an OLD run recorded (e.g. a
  `desktop.ini` row from pre-252 code) is removed on the next ingest because it is no
  longer in `seen_keys`.
- `IngestReport` fields are unchanged (`files_total`/`ok`/`failed`/`chunks`/
  `reused`/`skipped` all still count the supported files exactly as before).

### 2. `src/voice_agent/mcp_servers/docs.py` — no change needed

`_status()` builds `files` from `index.records()` and `failures` from
`index.failures()`; `DbIndex.failures()` is the generic
`SELECT ... WHERE status != 'ok'`, so the new `unsupported` rows appear in both
outputs exactly like other non-ok files (status, reason, mtime, size).

### 3. Spoken failure-count cap — unchanged, verified

"I couldn't read <name>: <why>." is built in
`pipeline/src/voice_pipeline/doc_route.py::new_failures_prefix`
(`MAX_FAILURE_NOTICES = 2`, overflow line "And N more files I couldn't read."). It
consumes the `failures` payload generically, so unsupported files count as unreadable
there with the cap intact; no code change.

### 4. `pipeline/tests/test_docs_first_routing.py` (additive)

- `test_new_failures_prefix_counts_unsupported_files`: two `unsupported` failures get
  their own "I couldn't read a.json: unsupported file extension: .json." sentences; a
  third is capped into "And 1 more files I couldn't read." and its name is not spoken.

### 5. `tests/rag/test_unsupported_recorded.py` (new, 6 tests, all synthetic)

- `test_unsupported_recorded_junk_ignored` — folder `a.json`, `b.odt`, `.DS_Store`,
  `c.md` → exactly 2 recorded `unsupported` (status/note/error/n_chunks/kind checked),
  `.DS_Store` not recorded, `c.md` ok, zero chunks for the unsupported files, all
  chunks belong to `c.md`.
- `test_supported_chunks_identical_to_alone` — ingest `c.md` alone, then add the
  unsupported files and re-ingest: chunk rows (source, section, text) identical to
  before, `c.md` row still ok with the same n_chunks.
- `test_reingest_idempotent` — second ingest over the same tree: `files` table and
  chunks byte-identical.
- `test_generic_junk_names_ignored` — `Thumbs.db`, `desktop.ini`,
  `__MACOSX/cache.json`, zero-byte `empty.json`, `~$draft.docx`, dotfile
  `.hidden.txt` (supported extension) + one real `d.md` → only `d.md` recorded.
- `test_reader_exception_is_recorded` — a file that raises in a reader (garbage-byte
  `.pdf`) is recorded with a non-ok status, an error message, 0 chunks, and appears
  in `DbIndex.failures()` (the ticket's "verify it is recorded" check).
- `test_docs_status_lists_unsupported` — `build_server(corpus, db=db)` in-process via
  fastmcp `Client`; `docs_status` lists both unsupported files in `files` (status
  "unsupported") and in `failures` (reason carries the extension); the supported file
  is in neither failures nor is `.DS_Store` anywhere.

## Behaviour changes (intended)

- Unsupported, non-junk files dropped in a folder are now visible to the agent:
  one `files` row each (status "unsupported"), named by `docs_status` and eligible
  for the capped "I couldn't read …" notice.
- Generic junk is never scanned or recorded. Concretely: `desktop.ini` is no longer
  parsed as `.ini` (it could have produced a chunk before); zero-byte files with a
  supported extension are no longer recorded as `empty` failures. Both have 0 chunks
  either way, so chunk counts/text of the files that do get indexed are unchanged.
- The live `DocIndex` path, the zip path, the `files`/`chunk_data` schema, and the
  `IngestReport` are unchanged.
