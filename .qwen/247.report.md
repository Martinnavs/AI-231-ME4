# 247 report: compound document+web questions are split and answered per lane

Branch `w/247`, worktree `~/AI-231-ME4-w247`. Pi results read first: `/tmp/zz240/pi2/RESULTS-c484bde-2026-11-27.md`, `run40/run40-c484bde.json`, `pi-agent-jsonl/20261126-194419.jsonl` (rows x04/x05/x08/x12/x14/x17/x20/x21/x28/x30).

## The bug

A question that needs BOTH a fact from the user's documents and the web (or a doc fact used inside a web question) was answered by one lane only. The document check saw the whole compound question, returned none/check_failed, and then either the web answered only its half (x28 "The UK prime minister in my briefing notes, is that still right?" → only the current-PM fact, the note's fact lost; x04/x12 the capital question lost the state; x17/x20/x21 lost the doc half) or the turn died at "The documents don't say." (x12/x30 in the `docs_miss` rows of the jsonl).

## What changed

### 1. `pipeline/src/voice_pipeline/compound.py` (new)

- `COMPOUND = True` kill-switch; `SPLIT_TIMEOUT_S = 2.0`; `COMPOUND_BUDGET_S = 7.0` (total, from the miss).
- `async def split(request, question) -> Split | None` — ONE call to `self.doc_json_request(system, user)` (the same cheap JSON model the document lane uses; signature reused exactly, `JsonRequest` imported from `ask_documents`). User content is `f"Question: {question}"` so the model classifies instead of answering. Any error / unparsable reply / timeout (2.0 s) → None. The system prompt is generic English with three synthetic examples on invented entities (the "Zorblat bureau", the "Quenth river"); no test-corpus words anywhere in the module. Output: `{"kind": "single" | "doc_then_web" | "doc_and_web" | "doc_vs_web", "doc_question", "web_question"}`; `doc_question` keeps the user's file/document reference; `doc_then_web` carries the literal `{doc}` placeholder; `doc_vs_web`'s `web_question` is the current-facts question; `single` → None (nothing changes).
- `async def answer(server, said, doc_s, session, on_text) -> dict | None`:
  - (a) doc half: `await server._ask_docs(split.doc_question, session)` — the checked document lane, its checks stand. A timeout/error there synthesizes a `DocResult("timeout"/"error")` only for logging.
  - (b) web half: if `{doc}` is present and the doc half was not accepted → None (fail-open: the web question cannot be asked). Otherwise `{doc}` is filled with the doc answer's core — `DocResult.answer` (the raw answer, no citation) falling back to `spoken` with the citation lead stripped via the same `partition(": ")` the document lane uses, first sentence — and `server.lookup("web_answer", {"query": web_q})` is called, so the ledger, the hedge and the 245 directness check all apply. Hedged (the web server's own "I couldn't confirm that with a search, so I won't guess." line, copied as in `evaluators.HEDGE`) or None → the doc half is spoken plus "I couldn't check the web part."
  - (c) combine: doc half accepted → doc sentence(s) then web sentence(s) (doc_then_web / doc_and_web / doc_vs_web all the same shape — the listener hears both facts); doc half not accepted but web half is → "Your documents don't say. " + web text (**doc_and_web only**, per the ticket).
  - (d) spoken via `server.spoken(text, on_text, ...)` with the normal docs-miss fields computed from the DOC HALF (docs status, doc_s — turn-start elapsed including the compound work — doc_calls, fallback, sources, rejected brief), plus `compound: true`, `compound_kind`. The route stays `docs_miss` (set by `_docs_miss_turn`; the hook runs inside it).
  - Every step is capped by the remaining 7 s budget; beyond it, None.
- `HEDGE_TAIL` is a copy of `evaluators.HEDGE` (which itself copies the web server's line; the AST test pins them together) — the established pattern for this string.

### 2. `pipeline/src/voice_pipeline/agent_server.py` (small, local)

- `__init__`: `self._compound_attempted = False`; `handle`: reset per turn right next to `self._docs_checked = False` (same pattern) — the split runs at most once per turn.
- `_docs_miss_turn` / `_docs_miss_answer`: new trailing kwarg `session: str = ""` (both existing call sites in `handle` pass `session or ""`), so the doc half's sources land under the turn's session.
- The hook in `_docs_miss_answer`, BEFORE the `DOCS_DONT_SAY` early return (a compound question with a document cue must not get "The documents don't say." immediately):

  ```
  if (compound.COMPOUND and not self._compound_attempted
      and doc_result.status in ("none", "check_failed")
      and doc_route.names_documents(said, doc_route.cached_files(self))):
      self._compound_attempted = True
      if (res := await compound.answer(self, said, doc_s, session, on_text)) is not None:
          return res
  ```

  The cheap gate is `names_documents` (the same one 243 uses for the miss prefix): only a miss that references the user's documents pays for the split. `None` falls through to the existing code unchanged.
- The ROUTER path (rows x20/x05: route "routed", docs check_failed) needs no second hook: it handles its miss through `_docs_miss_turn(..., web_fallback=_web_or_none)` (agent_server.py:1461), which calls `_docs_miss_answer`, so the same hook runs before the web fallback. Verified by `test_the_router_web_fallback_path_reaches_the_hook`.

Not changed (non-goals): `ask_documents.py` checks, the question gate, chain, the 245 directness check (it lives in the web server and is reached because the web half goes through `server.lookup`), `spoken_form`.

## Design decisions / notes

- **doc_vs_web with a rejected doc half** returns None (fall-through) — the ticket reserves the "Your documents don't say. " + web line for doc_and_web only, and a doc_vs_web question whose quoted fact the documents don't contain has no document fact to compare.
- **Production caveat (flagging honestly):** `doc_json_request` is built by `gemini_json_request`, which pins the document lane's `REPLY_SCHEMA` (status/answer/file/quotes/...) on the reply. Per the ticket the split reuses that exact request and expects `{"kind", ...}`; the parser is strict about `kind` and fails open. If the production model follows the pinned schema instead of the system prompt, the split returns None and the existing miss answer stands — the feature is dormant, never wrong. The scripted-fake tests (ticket-mandated) exercise the full behaviour. Worth a live check on the Pi; if the schema wins, the follow-up is a separate request builder, not a change here.
- `doc_s` in the result is the turn-start-elapsed time (the miss's `doc_s` plus the compound's own work), as the normal docs-miss turn logs it.
- Existing tests: **none updated.** No existing test asserted the old compound behaviour — the whole suite passes unchanged (the old behaviour was simply "one lane answers", which no test pinned for compound questions).
