## What was built

1. **Volatility cue list** (`pipeline/src/voice_pipeline/temporal.py`, one shared place
   next to `TIME_CUE_RE`): the ticket's 20 generic words, word-bounded with an optional
   plural, plus `strip_citation` (the "As per \<file\>(YYYY):" lead removed before
   scanning, so file names are never scanned) and `volatility_cues(question, answer)`.
2. **Gate** (`sufficiency.should_check`): a last leg — a cue in the question or the
   model's answer pays for the check. The confident-decision, time-sensitive,
   short-answer, pinned-past and source-earlier legs are untouched; the pinned-past
   exemption still suppresses the cue.
3. **Verdict** (`sufficiency.SYSTEM`): a fifth check, "5. Volatility check" — the
   generic class distinction (volatile: policies/defaults, schedules/deadlines,
   office/contact, prices/fees, officeholders, counts, "as of" statements; stable:
   definitions in law or science, arithmetic, history, names) in generic wording with
   five invented Zorblat/Quenth examples only. It fires only for a current-value
   question (explicit present/next-period question, or a fact whose current state is
   what is asked); a question about what the user's own documents say (their rules,
   requirements, thresholds, limits, deadlines, definitions) is not a current-value
   question — the document's settled statement is the answer and the doubt default
   applies; the check never revisits the period judgement of check 1.
4. **Volatility hint** (`sufficiency.verdict`): when the cue list matches, a
   "Volatility hint: … (cues). Work the period check first; the wording alone is not a
   verdict." line rides to the model — prompt input only; the cues never produce a
   verdict without the model.

No corpus words, file names, ids or row phrases in code or prompts.

## The two iteration-1/2 failures and their fixes

- **imp-049/imp-054/imp-056 controls over-trigger (iteration 1)** — timeless questions
  about the user's own settled rules came back `missing_half` ("a policy value, not
  shown current"). Fixed in iteration 2 by making the check fire only for a
  current-value question and carving out questions about what the user's own documents
  say. Iteration 2: over-trigger 0/14 both modes.
- **imp-006 stale→sufficient (iterations 1 and 2)** — a next-year question answered
  with the 2026 figure. A controlled diagnostic on the dev row (prompt varied one
  element at a time, 2 calls each) isolated the cause to the hint line's imperative
  "work the volatility check", which made the model confirm the 2026 figure as current
  and skip the  period mismatch (the iteration-2 prompt without the hint, and the 263
  prompt, both returned `stale`). Fixed in iteration 3: the hint now reads "Work the
  period check first; the wording alone is not a verdict." Iteration 3 lane: stale
  15/15 = baseline. The gold mode still flips imp-006 (both gold runs; the identical
  payload returned `stale` in both isolated diagnostic calls and in the lane run) —
  a borderline row on model noise, documented in the results doc, the only delta versus
  the 263 baseline.

Kept-run guard status: the best dev result is the 263 baseline itself (35/36 both
modes, 0 over-trigger) — iteration 3 reaches it only in lane (35/36) and misses one
borderline gold row (imp-006). The iteration-3 run met every hard guard (over-trigger
0/14 both modes; p50 0.58/0.59 s < 1.0 s; conflict 7/7; missing_half 13/14 = baseline;
gate share within 25%) but produced no dev gain, because dev conflict recall was
already 7/7 at baseline. "Keep the best" therefore keeps the 263 behaviour: the
orchestrator reverted the three 267 code commits (`git revert`) and recorded the
negative result under "Ticket 267 conclusion (orchestrator)" in the results doc. The
check's generalisation to the no-date-signal class (the full-100 conflict misses)
cannot be measured on dev by construction — next step per the conclusion: extend the
dev set with new conflict rows and measure on the real model before further prompt
work.
