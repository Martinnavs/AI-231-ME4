# ME4 status, 2026-11-24 (lean branch `lean/me4-pi`)

Owner spec: "This ME is basically the same as ME3. The only difference is it is going to base its answers on facts that can only be found in reference data or files. On the day of checking, you will be given a zip folder with documents of various forms (office, md, pdf, csv, etc). Your agent must be able to answer the query based on the facts stored in the documents. The answer may come from one or more documents plus other external sources such as the web."
Constraints: Raspberry Pi 4 (4 GB), Gemini only, spoken form terse ("As per <file basename>: <answer>", sources kept for follow-ups), never speak an unsupported answer, live spend: keep at least $0.10 of the $0.50 cap for test day. Professor (relayed): parse ON the Pi, files may be pre-parsed the day before; assume the database may NOT be built off the Pi, 1 h of preparation normally, 2 h at most.

## 3. Current issues (ranked)
**Product**
1. Routing. Only questions that say "the documents" or name a file take the checked, cited path. Plain questions go through the implicit route (passage-0 coverage >= 0.55, 2.5 s) or fall to the router; paraphrases always fall through (dev d-03). The docs-first rework (`qwen/201-wip`, gate 0.34 on best-of-top-3) let 28 to 52% of 25 non-document turns through the gate (each leak costs a Gemini call and about 1 s): NOT acceptable; needs a distinctive-word gate (target: >= 41 of 43 stored answerable pass, >= 90% of non-document turns gated out on each corpus).
2. `doc_race` (`agent_server.py` ~386-415) uses text-only passages: named-file questions are always rejected, the ordinal guard never fires (a wrong unnamed "first" answer is accepted), no "As per <file>" is spoken. Fix is in `qwen/201-wip`; do not swap `passages_of` alone, route those turns through the same docs function.
3. Documents plus web is at 0%: `agent_server` cancels the web lookup when docs win (`raced_lookup`, ~435-458). Design (Fable): a `WEB: <sub-question>` line in the doc prompt, then the existing grounded `web_answer`, spoken as "As per <file>: ... As per <site>: ...". A doc answer that fails the judge is never rescued by the web.
4. Spoken form is not terse on the shipped code (`doc_route.format_citation` speaks file path, section or page, date and the quote). Terse form and `citation_metadata` for the log are in `qwen/201-wip`. Sources checked are not kept: "which sources did you check?" cannot be answered (`handle_docs_turn` discards `searched`).
5. First/last questions on logs and CSVs are refused by the ordinal guard (correct answers too). Needs an ordered line scan; keep the guard for passages the scan did not produce.
6. Retrieval misses (dev): reworded (d-04), wide table (d-07), multi-file (d-10), doc+web (d-12). `q1`..`q4`, neighbour expansion and the per-file cap were measured by ticket 203 and change nothing; AND-first (`q3`) is worse. Table header paths (strip footnote digits such as `Revenue1`, carry the header path into each row chunk; ticket 109 territory), the 50,000-row CSV cap (Italy and Spain rows of the covid file are past it), cross-language and paraphrase rewrite (needs a live call on "none") remain.

Main system prompt (`pipeline/config/eval/system_agent.txt`): about 1,920 tokens, 56% of the prompt budget is the ME3 website-building "Case F"; Case C forbids `web_answer` (breaks doc+web), says "say you don't know" (fails the evaluator abstain phrase), and names "baby-onit"; `CHANGEABLE_NOTE` (`call_policy.py` ~668) may send document questions about a "latest/director/version" to the web (agy, not verified). Reports: `.scratch/me4-next/review/RESEARCH-agy-argon-prompt.md`, `RESEARCH-agy-prompt-modules.md` (core of about 215 tokens plus 6 routed skill files, skill router in `steer()`, prefix-cache-safe).
8. Remove "baby-onit" everywhere (owner: it stood for the docs RAG that now exists): `corpus/baby-onit` (16 files), `docs/CORPUS-BABY-ONIT.md` and mentions in other docs, Case C text, `agent_tools.py`, `call_policy.py`, tests, `agent_prompts.jsonl`, `Makefile`, `scripts/make_entities.py`. Do after the baseline (it changes prompt behaviour).
9. Scale: the FTS5 build holds all chunks in memory; database size at 1 GB text exceeds the Pi disk; scanned PDFs and images are unreadable by decision (OCR plan: rapidocr 3.10.0 + onnxruntime, phased, only after a 30-image Pi benchmark and image questions exist); `.doc`/`.ppt` need `catdoc` on the Pi (never run on a real file).

**Process and infrastructure traps**
- Qwen reports are unreliable (wrong line counts, "pre-existing failures", a stub called done). Re-run every Proof command; read the diff. Two retries, then implement.
- Stopping a Qwen run via its pid does NOT stop its Hermes session: the `hermes gateway` daemon keeps working in the worktree and can edit files (contaminated the baseline once). After a stop, check `ps -u $USER | grep hermes` and `git status`; copies of stray edits are in `.scratch/me4-next/201*-leftover.patch`.
- The pipeline venv (`pipeline/.venv`) lacks converters (30 of 44 files fail): build indexes with the root `.venv`, read them with `--db`.
- Shared `.venv` editable install points at another checkout: always set `PYTHONPATH=<worktree>/src:<worktree>/pipeline/src`.
- `--max-usd` is cumulative on the ledger: `remaining = 0.9 * cap - spent`. The live path needs the keyring patch (`/tmp/keyring.patch`, local only, NEVER commit; apply to a scratch worktree and revert).
- `tests/rag/test_canonical_spike.py::test_criterion_4_per_format_d5[csv_identity]` is flaky under load (passes alone).
- `git worktree add` onto an existing path silently reuses it: use a new path.
- Blind-set discipline: `~/rag-testsets/heldout/sealed.jsonl` is never read until the final run.
