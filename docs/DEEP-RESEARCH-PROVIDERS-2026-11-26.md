# Deep-research provider audit (2026-11-26)

Scope: official Gemini Deep Research/Interactions API and composable Tavily and Firecrawl retrieval services. This is a provider audit, not an architecture/framework survey (that is covered separately). No packages were installed and no provider APIs were called. Provider latency is **unmeasured here**; local timings below are repo's existing observations, not fresh benchmarks.

## What the repo already has

The repo already has two distinct web lanes. `web_answer` is a latency-bounded factual lookup: Gemini 3.1 Flash-Lite with Google Search when enabled, then Tavily, then Wikipedia ([gemini_grounding.py](../src/voice_agent/mcp_servers/gemini_grounding.py#L1), [tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L416)). `web_research` is a separate MCP tool described as raw search results that feed another step ([tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L433)). It tries a longer Gemini Google-grounded answer when credit policy routes that way, otherwise issues one or two Tavily **basic Search** requests, merges/deduplicates snippets, and caches for an hour ([tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L443), [tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L460), [tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L503)). `gemini_grounding.py` has a short-answer `SYSTEM_RESEARCH`, but calls `generateContent` with `google_search`; this is not the autonomous Deep Research agent.

The current code does **not** use the Gemini Deep Research agent or Interactions API, and it does not call Tavily Extract/Crawl or Firecrawl. Tavily search snippets/results are the current retrieval payload; no URL extraction stage enriches a selected page. Existing local comments report median 0.79 s for settled Gemini web answers and 1.21–1.24 s Tavily `fast` search; both were measured for simple lookups in Manila, not multi-source research ([gemini_grounding.py](../src/voice_agent/mcp_servers/gemini_grounding.py#L3), [tavily_search.py](../src/voice_agent/mcp_servers/tavily_search.py#L57)).

## Provider capabilities

| Option | What it supplies | Latency fit | Cost / control | Privacy and license |
|---|---|---|---|---|
| **Gemini Deep Research agent** | Managed multi-step plan, search/read, synthesis and cited report; supports user-provided documents, MCP tools, visualization and collaborative plan review. | Explicitly long-running: docs say several minutes. Interactions `background=true` returns an interaction ID; poll or stream progress. Not a spoken-turn response. Current docs list `deep-research-preview-04-2026` (speed/efficiency) and `deep-research-max-preview-04-2026` (comprehensiveness); agent remains preview and is Interactions-only. | Token billing includes intermediate input/reasoning generated by agent loops plus tool fees. Work amount and final bill are not fixed by one request parameter; record usage and set application-side budgets/cancellation. | Google says Gemini API Free tier content is used to improve products; Paid tier content is not. Background interactions are retained 1 day Free / 55 days Paid by default. Do not send personal or sensitive research prompts on Free. |
| **Tavily Search + Extract + Crawl** | Search returns ranked URL/title/snippet and optional answer/raw content; Extract fetches selected URLs (up to 20 per request) into markdown/text with per-URL success/failure; Crawl maps and extracts a bounded site traversal. This is a composable web-data layer, not itself an autonomous research reasoner. | Search can be a single network call. Extract adds calls and latency only for chosen sources. Crawl is explicitly bounded but can take much longer. Repo only has local search observations; provider latency for Extract/Crawl is unmeasured. | Tavily docs currently list 1,000 free credits/month; basic Search 1 credit, advanced 2; basic Extract 1 per 5 successful URLs, advanced 2 per 5; Crawl is map plus extraction. Costs are predictable per successful operation. Current existing service doesn't pay Extract/Crawl cost because it doesn't call those endpoints. | Tavily's API is hosted proprietary service; query and selected URLs/content are sent to Tavily. Privacy policy describes its service data processing; review retention/contract terms before sending sensitive prompts. SDK code licensing isn't the same as API/data terms. |
| **Firecrawl Search/Scrape/Crawl** | Hosted endpoints search and optionally scrape search hits; Scrape yields Markdown/HTML/structured output from a URL; Crawl traverses bounded site pages. Good alternate extractor or fallback for difficult web pages, not a synthesis model. The project also exposes MCP integrations. | Single scrape/search calls may suit source enrichment; crawl is a background, multi-page operation. No repo or provider latency measurements are available. Do not assume browser rendering is faster than a simple HTTP fetch. | Cloud plan/credit costs vary by endpoint and options; verify live pricing before adoption. Self-hosting trades API charges for infrastructure, network/browser maintenance, and operator time. | Firecrawl main repo is AGPL-3.0 (SDKs/some UI components MIT per repo statement); review component-level licensing before self-hosting or incorporating code. Cloud sends queries/URLs/content to Firecrawl; evaluate vendor privacy/security terms. |

## Recommendation for the product shape

Keep normal voice lookup and short web-research behavior on the existing fast path. A several-minute agent cannot meet turn-taking expectations; it should be an explicit **background research task**: acknowledge immediately, persist interaction/job ID and state, allow progress updates and cancellation, then deliver a cited report when finished. The report should retain per-claim source URLs and distinguish primary sources, contradictory evidence, and unresolved questions.

For an initial managed experiment, Gemini Deep Research is the shortest path to GPT-style autonomous planning and synthesis: Google operates the agent loop and supports background/streamed interactions. It is preview, its cost is variable by agent work, and it is not a low-latency substitute for `web_answer`. Use the standard version first; expose Max only if evals show a quality gain that justifies more work/cost. Start with Paid API usage if real user prompts can contain private information, and provide hard task-count/cost controls.

For an implementation that needs provider control or source recovery, augment the existing Tavily MCP lane with **search → choose candidates → Extract chosen URLs**. Keep Crawl for an explicit site-research request; it is unnecessary overhead for everyday open-web questions. Add Firecrawl only if a source set shows a meaningful extraction gap (JS-rendered or messy pages) that Tavily Extract cannot meet. Self-host Firecrawl is not automatically the cheap or simple choice: its AGPL server, browser/runtime operations, and crawler upkeep are part of the decision. The services can compose with a separately selected OSS orchestration/reasoning framework, but neither Tavily nor Firecrawl replaces that framework or the model that synthesizes evidence.

Before production, compare both research lanes on the same held-out prompts: time-to-acknowledgment, time-to-first useful progress, completion time, citations opening and supporting claims, source diversity/authority, missed or contradictory facts, total token/provider spend, timeouts/cancel behavior, and whether source pages survive in the final artifact. No provider-specific end-to-end latency or answer-quality result is claimed in this report.
