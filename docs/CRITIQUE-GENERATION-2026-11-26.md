# Generation, routing, and evaluation critique (2026-11-26)

Scope: adversarial review of the current document answer path, general catalogue lane, router/docs race, offline evaluations, runtime parity, and the numerical claims in `GEMINI-EDGE-AND-ENTERPRISE-RAG-VALIDATION.md`. This is a review, not an implementation. The local checkout has no applicable project `AGENTS.md`; the handoff and validation notes were read. Fable's referenced review directory is not present in this checkout, so this review uses the handoff's recorded Fable decisions, current code, and Pi REPORT3/REPORT4 evidence. HEAD is `8dbc4e3` (234 MCP string decoding fix). REPORT3 measures `324cd10`; REPORT4 measures HEAD on the same index and confirms recovery of catalogue queries and Texas document retrieval.

## Highest-risk findings

### P0 — Quote checks establish provenance, not support or entailment

`_run_checks` requires an answer to contain question-related terms/numbers, and a copied quote to appear in retrieved text (`ask_documents.py:721-800`). It does not establish that the quoted sentence entails the answer, that it is the right row/record, or that a comparison's answer follows from the quotes. The disabled `ROW_KEY_CHECK` (`:758`) leaves the known wrong-row case open. The allowed quote can be up to 30 words and is independent from the answer; matching a numeric token or proper name is not a semantic relation check.

This is observable, not hypothetical: the Pi report marks turn 5 wrong-path (Census fact missed; web answered instead), turn 6's arithmetic answer numerically right but prefixed with a false “couldn't confirm” because the document check rejected it, and turn 12 wrong because a 2026 value answered “next year.” The live round and handoff also recorded d-10 wrong-row acceptance and mileage-year false acceptance. The current checks did not cover the first failure class consistently and cannot determine freshness without a trustworthy source validity date.

**Experiments:** (1) create a blind, human-adjudicated challenge set of minimally different table rows, negation/absence, aggregation, temporal conflicts, and quote-present-but-non-entailing passages; report accepted-correct, false-accept, abstain, and wrong-source separately. Freeze it before tuning. (2) Compare current checks to a structured evidence contract requiring each answer claim to map to a span plus relation/row key and validity interval; keep the verifier deterministic where possible. (3) Keep a “quote-valid / answer-unsupported” counter from manual review; do not call quote pass a correctness proxy.

### P0 — Docs-plus-web is a lossy and weakly guarded composition

The model may emit `status="web"`, but after document checks the web result is appended as raw text and the overall `DocResult` becomes accepted (`ask_documents.py:986-1005`). There is no source/claim reconciliation, freshness check, or structured confirmation that the web answer answered the generated `web_question`. If web lookup fails, code still returns accepted document text with a caveat (`:1005-1014`); if no web callable exists, status `web` can fall through as a plain accepted document answer. This makes mixed answers look more complete than they are and creates a confusing failure mode for a spoken user.

The race path similarly treats any accepted document response as winner and returns before consuming the already-running web answer (`agent_server.py:515-533`). That is a latency optimization, but it discards potentially fresher evidence on exactly the questions where currentness matters. The Pi REPORT3 has two live examples: population question went to web after docs `check_failed`; “next year” was answered with the stale 2026 document value, no date cue. The handoff says the live card/year wiring was deferred. Current temporal tagging derives one year from a card and only annotates the spoken source (`ask_documents.py:978-985`); it does not compare the source period to the requested period or reject stale material.

**Experiments:** add a small adjudicated split with document-only, web-only, mixed answer, contradictory sources, failed web, and “next year/current/latest” cases. Score whether both halves are answered and identify source/date for each half. Compare race policies: current first-valid-doc, web-first on temporal cues, and short bounded wait for both with deterministic date conflict resolution. Measure P50/P95 first audio and false-freshness separately. Require a clear partial-answer state when one half is unavailable.

### P1 — `none` conflates an empty corpus with service/index failure

`answer_general` returns `status="none"` whenever catalogue is empty (`general.py:119-121`); `_docs_general_turn` maps that status to “Your documents folder is empty” (`agent_server.py:773-777`). Pi REPORT3 shows the actual corpus had 48 files / 13,898 chunks, while both catalogue questions got that empty-folder sentence in 0.05 s. The exact cause was unverified in the run-only report; HEAD 234 subsequently fixed MCP string decoding in this lane and `file_has`, and REPORT4 confirms both catalogue questions now answer on the Pi. Texas population also now returns from the census document. The prior observed defect is fixed for these cases; malformed/failed results still need distinct semantics. A transient tool/decode/transport failure must not be represented as a true empty corpus.

**Experiments:** assert the runtime catalogue count against ingest/index health at startup and run the two catalogue questions through the real MCP transport on the deployed Pi. Preserve distinct `empty`, `unavailable`, and `decode_error` states; only say empty when a successful status response confirms zero files. Add regression checks for both structured MCP content and string-encoded JSON at the transport boundary.

### P1 — Routing and branch parity remain empirically under-proven

The 11:25 handoff states ticket 233 shared general/no-answer helpers across router and no-router branches, and REPORT3 at `324cd10` includes that change. Both REPORT3 and REPORT4 were launched with `NO_ROUTER=1`; neither validates router-on deployment. The user-required path is pure audio with VAD on Pi, STT/TTS on the external laptop, and router commands plus agent/MCP on Pi. Handoff explicitly says spoken path, first-audio latency, speech vocabulary effect, and doc+web live behavior were unverified. Offline pipeline/root suites prove code-level regressions but not Pi service launch arguments, MCP serialization, audio path, or model behavior.

**Experiments:** use one frozen deployment archive and execute the actual systemd `HARNESS=pi` launch with router on, audio I/O on the laptop, plus one command, one general catalogue request, one explicit document request, one mixed doc+web request, and one injection/secret trap. Record commit, argv/env (redacting secrets), route, MCP payload shape, first audio, final answer, and per-stage latency. Compare no-router only as a diagnostic. After 234, specifically verify string decode for catalog and `file_has` against the actual deployed MCP server.

## Evaluation design and leakage

### Offline “oracle” is a rule simulator, not a model-quality estimate

`AnswerOracle` is given the gold row and returns `accept[0]` whenever annotated facts are present (`scripts/me4_ask_eval.py:92-134`). It selects the quote from the gold `contains`/`accept` terms. `TemptedOracle` is deliberately adversarial but also handcrafted: select the line with most lexical query terms and emit its first number/proper name (`:137-161`). This usefully probes deterministic checks, but cannot predict Gemini/Qwen answer behavior, reasoning errors, answer style, or calibration. It can overstate answerable coverage and understate false acceptance; the handoff itself records a tempting-oracle wrong-row limitation where it quotes the right row on wrong-row traps.

The offline web callback is also an oracle (`:193-194`): it returns the row's expected text, without search failure, source conflict, latency variation, or a wrong web result. The summary counts “accepted-correct” against answer/expected strings (`:213-243`), so the result is a narrow checker compatibility metric, not end-to-end grounded QA accuracy.

### Dataset reuse and tuning overfit

Handoff records repeated changes against the same dev/golden/A/B and golden-v2 sets (including stoplist tuning and threshold-like conditions), then reports stable counts. Stable scores after modifications do not establish generalization when examples informed the implementation. The sealed set was run once and explicitly burned; it should not be reused. Treat named suites as development data from this point. Pi REPORT3 is valuable external-runtime evidence but the 16 turns are known and the “ok_hint” is not independent correctness adjudication; only 12/16 were judged right, with soft/unverified rows.

**Experiments:** freeze a new untouched temporal/table/negation/mixed-source holdout with adjudicated answerability and accepted evidence spans; ideally include counterfactual pairs differing by a single row/date. Have two reviewers independently label and resolve disagreements. Do not expose these cases to implementers until release candidate lock. Report confidence intervals (or raw counts for small n), false accepts and false rejects separately, and results by slice. Run one live model call per case only at the chosen candidate and preserve raw traces without using the holdout for tuning.

### Entry eval can test routing mechanics while missing real route outcomes

`me4_entry_eval.py` supports fake router/agent paths, and `doc_oracle` defaults to a deterministic answer oracle (`:427-432`; docs-first wiring at `:435-470`). Route summaries infer web calls by parsing router output text (`:250-260`), not by confirming the production web service returned useful, sourced content. These are good controlled harnesses for branch/latency behavior, but must not be merged into a single “accuracy” claim with the real model path. Report router correctness, route selection, retrieval, answer verification, and spoken output independently.

### Runtime parity gaps

Offline `_run` injects `card=db.file_card` and uses direct `DbIndex` methods (`me4_ask_eval.py:187-212`), while Pi deployment depended on external MCP tools and, per handoff, the T3 card wiring had not been connected to the live call. This can make temporal test behavior differ from runtime. The regression report's 1308+ tests do not close that behavioral gap. REPORT3 at `324cd10` includes `16ff30c`; REPORT4 measures HEAD 234. The latter confirms catalogue/Texas recovery but still lacks router-on audio evidence and still returns the stale next-year value.

**Experiment:** contract-test the same cases through both direct functions and a real MCP wire adapter, then run a smaller end-to-end set on the frozen Pi build. Compare normalized tool inputs/outputs and route decisions, not just final status. Add explicit tests where optional capabilities (`card`, `file_has`, catalog) are absent or return errors.

## Numerical claims audit in `GEMINI-EDGE-AND-ENTERPRISE-RAG-VALIDATION.md`

The document overstates several results as universal engineering prescriptions. The audit found these high-impact corrections:

| Claim | Audit | Change in interpretation |
|---|---|---|
| Spotlighting datamarking gives 3.1% ASR (validation lines 21, 217-229) | The primary Spotlighting paper reports reductions from >50% to **below 2%** across its experiments, with task/model-specific results. Its abstract does not support presenting 3.1% as a general validated ceiling, nor a guarantee for Gemini Flash-Lite/Haiku. The recommended source currently links a blog summary, not the primary paper. | Cite the paper and specify model, task, attack set, and setting for every ASR. Keep it as a candidate mitigation to test locally, not a `<5%` assurance. [Hines et al., arXiv](https://arxiv.org/abs/2403.14720) |
| CRAG 43.6% accuracy / 13.4 truthfulness (lines 182-188) | These figures are consistent with the CRAG paper's GPT-4 Turbo web+KG task result, but they are not a general property of RAG. The truthfulness metric is benchmark-defined and auto-evaluated; task setup uses fixed retrieved contexts. The validation links a third-party summary rather than the NeurIPS primary paper. | Cite [the CRAG paper](https://papers.neurips.cc/paper_files/paper/2024/file/1435d2d0fca85a84d83ddcb754f58c29-Paper-Datasets_and_Benchmarks_Track.pdf), label the exact task/model/evaluator, and use the metric as an evaluation idea rather than as an invariant score. |
| Retrieval degrades Gemini 2.5 Flash-Lite by 19.7%, PoT cuts arithmetic errors 88% (lines 11, 106, 117, 355) | The cited sources are 2026 preprints with narrow dataset/task/model conditions; the source list points to FinTradeBench and FinAgent-RAG papers but prose turns their results into a broad routing rule. The 88% is not proof that an arbitrary sandboxed Python tool will remove this system's arithmetic errors; extraction, row selection, units, and date validity remain upstream failure modes. | Keep these as hypotheses. Reproduce on the local corpus with measured end-to-end exactness, including extraction/row selection and unit handling, before adding code execution. Report absolute and relative deltas and sample sizes. |
| “Un-reranked hybrid” 30.4 vs naive 32.9 F1 (lines 22, 129-132) | This is a particular FinanceBench preprint/configuration, not evidence that hybrid retrieval should never be used without reranking. The source table and exact pipeline need to accompany the point; a single benchmark does not establish a universal baseline ordering. | Recast as a caution that hybrid fusion can add noise and must be evaluated per corpus. The project's own RAG report shows retrieval choices vary by set; test recall and answer quality on this corpus. |
| GraphRAG global 10.10 vs vanilla 56.33 on TimeQA; RRF + reranking, OCR threshold, FTS5 tokenchars, Zip Slip/bomb numbers (lines 22, 131-162, 351-356) | These combine heterogeneous benchmark claims, implementation advice, threat classes, and an arbitrary pass bar into one “validated” matrix. Some references are vendor/blog or non-primary, and the proposed `r(p)>0.8` threshold, 10 MB bomb cap, and expected retrieval gains are not derived from this project's workload. | Separate literature evidence from local recommendations; remove “mandate” language. Set caps from resource budget and corpus constraints, and measure parsing/retrieval gains with representative files. |
| 2026 agent/security numbers (INFUSE, Odile, EnterpriseRAG, IA-RAG and others) | The repo document includes post-cutoff / 2026 claims, but several citations are secondary, preprint, or conference proceedings without enough detail to verify the exact aggregates from the citation as presented. A study's reported ASR/utility under its benchmark is not a deployment risk estimate. | Each row needs primary-source URL, exact table/section, model, benchmark subset, n, judge method, and date/version; otherwise remove exact percentages and don't label them “validated.” |

Primary source checked for the CRAG and Spotlighting assertions: the [NeurIPS 2024 CRAG benchmark paper](https://papers.neurips.cc/paper_files/paper/2024/file/1435d2d0fca85a84d83ddcb754f58c29-Paper-Datasets_and_Benchmarks_Track.pdf) and [Hines et al., “Defending Against Indirect Prompt Injection Attacks With Spotlighting”](https://arxiv.org/abs/2403.14720). Search results for Spotlighting report below 2% in the paper summary, inconsistent with treating 3.1% as a universal benchmark point. The numerical claims around FinTradeBench, FinAgent-RAG, FinanceBench, IA-RAG, EnterpriseRAG, INFUSE, and 2026 graph comparisons were not independently reproduced in this review; present them as unverified until source tables are cross-checked.

## Priority experiment sequence

1. **Production-health semantics:** preserve REPORT4 as confirmation that catalogue/enumeration work through the Pi MCP protocol, then check failure and truncation cases. Empty corpus, unavailable server, malformed/string MCP result must be three observably different outcomes. This directly targets Pi REPORT3 turns 9-10.
2. **Blind support/freshness challenge:** freeze a held-out set with wrong-row, negation/absence, conflicting dates, stale “next year,” and mixed docs+web examples. Human labels include answer, evidence span, row identity, and source date. No oracle generation based on `facts` at scoring time.
3. **Current model, actual runtime:** run the selected candidate once through the intended router-on pure-audio stack. Preserve final text, first audio, full stage timings, tool calls, MCP wire values, and independent correctness labels. Include the mixed doc+web case missing from the Pi REPORT3 evidence.
4. **Ablate guardrails:** compare current checks, current checks plus row identity/temporal constraints, and a structured claim-to-evidence verifier. Tune only on development splits; choose by false-accept reduction under a fixed false-reject and latency ceiling.
5. **Routing policy:** compare docs-first vs web for temporal and dynamic questions, then the bounded parallel race. Measure answer freshness and correct abstention as well as P50/P95 audio onset. Don't compare only route labels or completion time.
6. **Research-informed optimizations only after baseline:** consider header-aware chunks, table-aware retrieval, or deterministic arithmetic after an experiment shows the local failure source is retrieval, extraction, or calculation respectively. Don't import vendor headline gains as acceptance targets.

## What remains unresolved for the current release?

The present guardrails reduce obvious unsupported outputs, but a verbatim quote is only provenance evidence. REPORT4 confirms the catalogue false-empty fix on the Pi. Remaining release gaps include stale temporal answers, wrong-row risk, incomplete arithmetic, and mixed docs+web answers without evidence reconciliation. Offline suites are useful regressions for checker logic but should not stand in for blind model evaluation or the final router-on voice path. The 14/16 REPORT4 hint score is not strict task accuracy: the document half is missing in turn 11, the Guam answer changes period and unit in turn 13, and turn 6 omits the requested difference. Final verification still needs the router-on voice path and independent checking of table values and folder counts.
